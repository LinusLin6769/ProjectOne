# AI cost alternatives (T-011)
## Constraints (from the user directly)
- Hardware: MacBook with Apple **M2 Pro**, **16GB unified memory**.
- Usage: AI spend is **mostly agentic coding/orchestration work** (Warp/Oz), not a broad mix of other AI tools.
- Goal stated explicitly: not cost-constrained, not dogmatically anti-paid — wants a real survey of genuinely open/free options, not just a different paid vendor (BYOK to another API is not the ask).
## The core tension
16GB of *unified* memory (shared by macOS, every open app, and the model — not dedicated VRAM) caps what's locally runnable to roughly 7B–8B parameter models comfortably, 14B tight-but-possible with little else running, and nothing near 32B. Meanwhile the workload that's actually costing money is **multi-step agentic orchestration** (planning, multi-file edits, tool use across a whole session) — precisely the capability that drops off fastest as model size shrinks. Autocomplete/single-file/well-scoped tasks hold up fine on small local models; the parallel-worktree, multi-track orchestration this repo does does not. That mismatch is the headline finding below.
## Open-source coding-agent CLIs (model-agnostic, BYOK-or-local)
All of these are free software; you pay only for whatever model you point them at (including $0 for a local model). Names and shapes are stable/well-established projects — the general landscape:
- **Aider** (Apache 2.0, terminal) — the most git-disciplined option: every change is an auto-commit, has a repo-map for large-codebase awareness, and sends noticeably fewer tokens per turn than full-file-rewrite tools. Weakest on full autonomy (it's a pair-programmer, not a fire-and-forget worker) but the cheapest and most reviewable by design. Best fit for well-scoped, single/few-file tasks — exactly the tier that a local 7B model can handle.
- **Cline** (Apache 2.0, VS Code extension) — approval-gated (you click through each file edit/command), broad model support including Ollama/LM Studio for local models. More autonomous than Aider but reads more files per task, which burns more tokens/is slower on a local model.
- **OpenHands** (MIT, Docker sandbox) — the most autonomous open agent (runs end-to-end in a sandbox, opens PRs). Needs Docker, heaviest setup, and its own docs/community benchmarks are explicit that quality drops sharply below ~32B models — a 16GB Mac is not a good fit for this one.
- **Goose** (Apache 2.0, Linux-Foundation/Block-backed) — vendor-neutral, MCP-native, both CLI and desktop app, runs any provider including local. Good "Switzerland" option if MCP-server composability matters more than raw agentic strength.
- **Continue** (Apache 2.0, VS Code/JetBrains) — more autocomplete-and-chat than full autonomous agent; some sources report its main upstream repo has slowed/gone read-only after an acquisition — treat as lower-priority, worth rechecking current maintenance status before investing time.
None of these close the capability gap with Warp/Oz for the kind of parallel, multi-track orchestration this repo relies on — that gap is a function of model capability (frontier vs. small open-weight), not the harness. Swapping the harness alone doesn't buy back the cost; swapping the *model* down to something local is what both saves money and costs capability.
## What's realistically runnable locally on this Mac (M2 Pro, 16GB)
The leading open-weight coding model family is **Qwen2.5-Coder** (Alibaba, Apache 2.0, no usage caps) — it's the model most guides converge on as the best-in-class open coding model per size class, with **DeepSeek-Coder-V2-Lite** (MoE, 16B total/2.4B active) as a solid alternative especially for algorithmic work.
- **Qwen2.5-Coder 7B** (~5GB at Q4 quantization) — the comfortable default on 16GB unified memory. Genuinely strong for single-file generation, bug fixing, explanations, tests, and small refactors. This is the realistic daily-driver size for this hardware.
- **Qwen2.5-Coder 14B** (~9-10GB at Q4) — noticeably stronger on multi-file reasoning, but tight on 16GB once macOS, Warp, a browser, etc. are also resident. Usable, but expect to close other apps or accept slower generation from memory pressure/swapping.
- 32B+ models are out of reach on this hardware (need ~20-24GB just for weights).
**Runtime**: **Ollama** is the pragmatic default — one-command install (`ollama pull qwen2.5-coder:7b`), OpenAI-compatible local API (`localhost:11434`), and every tool above (Aider, Cline, Continue, Goose) already knows how to talk to it. **MLX** (Apple's native framework) is faster on Apple Silicon, but its biggest wins concentrate on 32GB+ Macs — on a 16GB M2 Pro the gap over Ollama's default Metal backend is smaller and the extra Python/setup friction is less worth it. Not worth the switch here; can revisit if RAM increases later.
## Genuinely free/open infrastructure worth knowing about
- **Warp's client is now open-source (AGPL-3.0)** — the terminal/ADE client itself, not the Oz cloud orchestration layer (which stays proprietary). Doesn't change the token-cost equation directly, but confirms Warp's direction is toward more openness, not less.
- **Warp's BYOK is free for individuals on every plan, including Free** — if you bring your own API key or point Warp at any OpenAI-compatible endpoint, Warp doesn't charge credits for that usage. This is BYOK-to-a-vendor (which isn't what you asked for), but the *same mechanism* is how you'd eventually point Warp directly at a **local** model.
- **Warp has explicitly announced (not yet shipped as of this writing) a lightweight local-model client harness** that would let Warp connect directly to a local model (e.g. an Ollama endpoint) without routing through Warp's servers and without login. Worth watching — if/when this ships, it would let you use Warp's own interface with a $0 local model for at least a slice of tasks, no separate tool needed.
- Nothing else surveyed (Aider/Cline/Goose/etc.) has hidden costs beyond the model you choose — they're all genuinely free software.
## Recommendation
**Adopt now (low lift, real $0 upside):** Install Ollama + `qwen2.5-coder:7b`, and use **Aider** against it for well-scoped, single/few-file coding tasks — quick scripts, small feature edits, boilerplate, DIY-panel-style code, test writing, explaining unfamiliar code. This is a ~15-minute setup, costs nothing to run, and Aider's git-native discipline (auto-commit per change) fits this repo's existing git-first culture well. Use it as a *first pass* for simple, mechanical coding work before reaching for a paid agent.
**Don't expect this to move the needle on the actual Warp/Oz spend.** That spend is driven by multi-track agentic orchestration — parallel worktrees, cross-file reasoning, long planning sessions — which is exactly where small open-weight models (7B, even 14B) fall furthest behind frontier hosted models. Running OpenHands or Cline locally on this hardware for that class of work would trade real reliability for a cost saving that's probably not worth it given the user's stated goal isn't cost-minimization for its own sake.
**Bigger lift, not recommended right now:** Upgrading to a 32GB+ Mac would unlock 27-32B models (closer to genuinely competitive with hosted models on many coding tasks) and MLX's full speed advantage. That's a hardware purchase decision, not a software one — flagging it as the real ceiling-raiser if local inference becomes more of a priority later, but not something to act on today.
**Realistic shift-off estimate:** Maybe 10-20% of day-to-day coding-adjacent work (the simplest, most mechanical slice) could move to a free local Aider+Ollama setup at effectively no quality cost. The bulk of what drives spend — the parallel multi-agent orchestration this repo is built around — has no genuinely open substitute yet at comparable quality on this hardware. The honest conclusion is: worth doing the free thing for the free thing's sake, not worth restructuring the workflow around it.
